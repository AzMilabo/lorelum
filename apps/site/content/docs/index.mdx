Lorelum turns team engineering experience into discrete, retrievable, trigger-conditioned units called **Practices**, and injects them into AI context at the moment of need.

<Callout type="info">
This page exercises Fumadocs on TanStack Start: MDX components, Shiki highlighting, tables, and search must all work in one static-renderable app.
</Callout>

## How retrieval works

Two kinds of clues drive retrieval:

- **Task** — what the agent is doing right now.
- **Moment** — which part of the development lifecycle the agent is in.

<Tabs items={['Task', 'Moment', 'Combined']}>
  <Tab value="Task">
    Building an auth flow, changing a database schema, writing component tests.
  </Tab>
  <Tab value="Moment">
    Starting to understand a complex requirement, recovering after compaction, deciding whether to change a failing test.
  </Tab>
  <Tab value="Combined">
    The caller describes both; Lorelum ranks the relevant Practices.
  </Tab>
</Tabs>

## Example query

```text
$ lore query "I'm building the RBAC admin panel and I'm about to claim the whole capability is done."
```

### TypeScript

```ts
import { retrieve } from '@lorelum/engine';

const result = await retrieve({
  task: 'building the RBAC admin panel',
  moment: 'about to claim completion',
});
```

### Shell

```bash
lore query "building the RBAC admin panel"
```
